## 3. 핵심 문제 및 해결 방법 (Problem & Solution)

### 문제 1: Push-To-Talk(PTT) 버튼 기반 마이크 수음 제어
- **증상 및 원인**: 
  - 마이크가 항상 켜져 있으면 주변 소음이 지속 전송되어 불필요한 대역폭 차지 및 노이즈 발생.
  - I2S DMA 버퍼에서 L/R 인터리브 데이터 정렬이 어긋나면 깨진 소리가 전송됨.
- **해결 방법** ([audioPass.c](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/hw/driver/audioPass.c)):
  - `USER_BTN` (Pull-Up) 상태를 실시간 확인 (`HAL_GPIO_ReadPin() == GPIO_PIN_RESET`).
  - 버튼을 누른 동안에만 유효한 PCM 오디오를 수집하고, 뗐을 때는 `0`(무음)으로 마스킹.
  - I2S 32비트 슬롯 중 실제 유효 PCM 데이터가 담긴 상위/하위 바이트를 16비트 Mono로 정확히 다운샘플링하여 `AUDIO_FRAME_SAMPLES`(128 샘플 = 256 바이트) 프레임 단위로 생성.

```c
/* 버튼 상태 확인 및 무음 마스킹 */
bool is_mic_active = (HAL_GPIO_ReadPin(USER_BTN_GPIO_Port, USER_BTN_Pin) == GPIO_PIN_RESET);
for (int i = 0; i < AUDIO_BUF_SIZE; i += 2) {
    int16_t sample = mic_dma_buf[i];
    if (!is_mic_active) sample = 0;
    temp_mono_frame[tx_idx++] = sample;
    // ...
}
```

### 문제 2: 오디오 바이너리 스트림과 주차 텍스트 패킷의 UART 공유 (Multiplexing)
- **증상 및 원인**:
  - 고속 오디오 바이너리 데이터(`128 samples = 256 bytes`)와 주차 상태 문자열(`$PARK,...`)이 하나의 UART를 통해 송신될 때 패킷이 뒤섞이거나 전송 지연 발생.
  - DMA 전송 중 새 프레임 생성 시 버퍼 충돌(Race condition) 발생.
- **해결 방법** ([UARTTX.c](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/hw/driver/UARTTX.c)):
  1. **바이너리 오디오 프레임 규격 정의**:
     - Header: `0xAA`, `0x55` (2 bytes)
     - Payload Length: `0x0100` (256 bytes, Little-Endian, 2 bytes)
     - Payload: PCM Mono 16-bit 128 samples (256 bytes)
     - Checksum: Header~Payload 전 구간 XOR 연산 (1 byte)
     - 총 프레임 크기: `261 Bytes`
  2. **Ping-Pong TX 버퍼 적용**:
     - `audio_frame_buf[2][AUDIO_PACKET_TOTAL]`를 선언하여 DMA 송신 중에 새 프레임이 이전 버퍼를 덮어쓰지 않도록 더블 버퍼링 적용.
  3. **주차 상태 패킷 최적화**:
     - 주차 슬롯 상태가 변경되었을 때만(`prev_slot_mask != current_slot_mask`) 가벼운 타임아웃(50ms)으로 전송.

```c
/* Ping-Pong 버퍼 스위칭 및 XOR 체크섬 */
uint8_t *p_buf = audio_frame_buf[frame_buf_idx];
frame_buf_idx = (frame_buf_idx + 1) % 2;

p_buf[0] = 0xAA;
p_buf[1] = 0x55;
p_buf[2] = (uint8_t)(AUDIO_PAYLOAD_SIZE & 0xFF);
p_buf[3] = (uint8_t)((AUDIO_PAYLOAD_SIZE >> 8) & 0xFF);
memcpy(&p_buf[4], (const uint8_t *)pcm_samples, AUDIO_PAYLOAD_SIZE);

uint8_t checksum = 0;
for (int i = 0; i < 4 + AUDIO_PAYLOAD_SIZE; i++) {
    checksum ^= p_buf[i];
}
p_buf[4 + AUDIO_PAYLOAD_SIZE] = checksum;

if (COMM_UART.gState == HAL_UART_STATE_READY) {
    HAL_UART_Transmit_DMA(&COMM_UART, p_buf, AUDIO_PACKET_TOTAL);
}
```

### 문제 3: 고속 오디오 수신 시 UART 패킷 누락 및 Overrun(ORE) 방지
- **증상 및 원인**:
  - 일반 인터럽트 수신(`HAL_UART_Receive_IT`) 방식은 CPU 부하가 높고 수신 패킷이 밀려 Overrun Error(`ORE`) 발생 시 수신이 정지됨.
- **해결 방법** ([UARTTX.c](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/hw/driver/UARTTX.c)):
  1. **Circular DMA 수신 (`RX_DMA_BUF_SIZE = 1044 bytes`)**:
     - 4프레임 이상의 크기를 갖는 원형 버퍼를 할당하여 CPU 개입 없이 DMA가 지속적으로 수신.
  2. **DMA 하드웨어 카운터 기반 실시간 파싱 (`commUartProcessRx`)**:
     - `__HAL_DMA_GET_COUNTER(COMM_UART.hdmarx)`를 읽어 `write_ptr`와 `rx_read_ptr` 사이의 수신 데이터를 FSM(유한 상태 머신)으로 파싱.
  3. **FSM 기반 패킷 파서 & 에러 자동 복구**:
     - `0xAA` -> `0x55` -> 길이 확인 -> 256바이트 수신 -> XOR 체크섬 검증.
     - `HAL_UART_ErrorCallback`에서 ORE/FE/NE 에러 플래그 클리어 후 DMA 즉시 재시작.

```c
void commUartProcessRx(void) {
    uint16_t write_ptr = (RX_DMA_BUF_SIZE - __HAL_DMA_GET_COUNTER(COMM_UART.hdmarx)) % RX_DMA_BUF_SIZE;
    while (rx_read_ptr != write_ptr) {
        uint8_t b = rx_dma_buf[rx_read_ptr];
        rx_read_ptr = (rx_read_ptr + 1) % RX_DMA_BUF_SIZE;
        commUartParseByte(b);
    }
}
```

### 문제 4: 수신 오디오의 Jitter 없는 스피커 재생 (DAC/PWM 변환)
- **증상 및 원인**:
  - 패킷 수신 주기와 오디오 샘플 재생 주기가 완벽히 동기화되지 않아 소리가 끊기거나 버벅거림(Audio Underflow/Overflow).
- **해결 방법** ([audioPass.c](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/hw/driver/audioPass.c)):
  1. **오디오 링 버퍼 (`RING_BUF_SIZE = 2048`) 완충**:
     - UART 수신 콜백에서 파싱 완료된 PCM 데이터를 링 버퍼에 적재(`audioPushToRingBuffer`).
  2. **TIM1 타이머 인터럽트(16.6kHz)를 통한 정주기 재생**:
     - 100kHz 타이머 베이스 인터럽트에서 6분주 카운터를 두어 16.6kHz 속도로 링 버퍼에서 샘플을 1개씩 소비.
  3. **16비트 PCM -> PWM Duty 변환 (`pcm_to_pwm`)**:
     - `-32768 ~ +32767` 범위의 16비트 오디오 샘플을 `0 ~ PWM_ARR_MAX (839)` 듀티비로 선형 변환하여 `TIM1->CCR1` 레지스터에 기록.

```c
static inline uint16_t pcm_to_pwm(int16_t sample) {
    int32_t duty = ((int32_t)sample * (PWM_ARR_MAX / 2)) / 32768 + PWM_MID_DUTY;
    if (duty < 0) duty = 0;
    if (duty > PWM_ARR_MAX) duty = PWM_ARR_MAX;
    return (uint16_t)duty;
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM1) {
        static uint8_t div_cnt = 0;
        if (++div_cnt >= 6) {
            div_cnt = 0;
            if (ring_tail != ring_head) {
                int16_t sample = audio_ring[ring_tail];
                ring_tail = (ring_tail + 1) % RING_BUF_SIZE;
                TIM1->CCR1 = pcm_to_pwm(sample);
            }
        }
    }
}
```

### 문제 5: 10개 주차 슬롯 확장 및 메인 루프 구조 정리
- **증상 및 원인**:
  - 기존 6/8개 슬롯에서 10채널 CDS 센서로 확장되면서 8비트 마스크 초과 (`uint16_t` 필요).
  - `appInit()` 내 분산되어 있던 타이머, PWM, DMA 시작 코드로 인해 초기화 순서 종속성 발생.
- **해결 방법** ([appMain.c](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/app/appMain.c)):
  - `uint16_t current_slot_mask`를 도입하여 10개 채널(0~9)을 `(1U << i)`로 비트 마스킹.
  - [audioInit()](file:///c:/Users/kccistc/ParkingLotSystem/ParkingDetect/MyApp/hw/driver/audioPass.c#L51) 내부로 타이머 설정, PWM 활성화, Base IT, I2S DMA 시작을 캡슐화하여 초기화 과정 단일화.
  - `appMain()` 내에서 `commUartProcessRx()`를 상시 호출하여 패킷 수신 지연 제거.

## 5. 결론 및 성과

1. **안정적인 양방향 오디오 통신 달성**:
   - I2S DMA 마이크 수음 -> UART TX DMA 송신 -> 상대측 UART RX DMA 수신 -> 링 버퍼 -> TIM1 PWM 스피커 출력 파이프라인 완성.
2. **패킷 유실 및 깨짐 방지**:
   - XOR 체크섬, 헤더 검증, Ping-Pong 더블 버퍼링, Circular DMA를 결합하여 통신 안정성 확보.
3. **주차 감지 및 오디오 동시 운영**:
   - 10채널 CDS 센서의 상태 변화 이벤트와 실시간 오디오 스트림이 충돌 없이 원활히 동작하도록 멀티플렉싱 구조 완성.
